# Bug 修复日志

## Bug 3.6-1：中文搜索无高亮且输入框显示口口（2026-07-25）

- 症状：Play 模式下在搜索框输入中文，字符显示为口口；没有任何格子高亮。
- 复现：打开背包，切中文输入法输入"苹果"。
- 用户初判：中文字符乱码导致搜索失败。
- 实际原因（已定位，两个独立问题，初判不成立）：
  1. 不高亮：场景中 `itemDefinitions` 的 `displayName` 是英文（`Apple`、`Stone`，main.unity 6288/6294 行），中文输入不可能命中任何名称；输入框里的字符串数据本身完好。
  2. 口口：项目内仅有 `LiberationSans SDF` 字体资产（无中文字形）；TMP 对字体图集中缺失的字形渲染为方块，只影响显示、不影响字符串值。
- 顺带发现：`ApplySearch()` 的 `Contains` 是大小写敏感的序数比较，英文数据下输入 `apple` 无法命中 `Apple`；原保守假设"中文名下大小写无关紧要"被真实数据推翻。
- 修复（第一部分，2026-07-25）：匹配改为 `Contains(trimmedText, System.StringComparison.OrdinalIgnoreCase)`——忽略大小写在所有修复方向下都需要，按保守默认直接实施；编译 0 错误。
- 修复（第二部分）：是否将数据改为中文名并引入中文字体（原方案 B），仍待用户决定；不阻塞英文输入下的行为验证。
- 验证：用户已于 2026-07-31 用英文输入完成流程 3.6 的 8 项 Play 行为清单；小写完整名、部分名、多结果、无结果、清空、刷新跟随和模态交互均通过，修复确认有效。
- 启发的早期决定：流程 1.2 放入示例数据时选择了英文名，而用户的搜索心智模型是中文名——数据语言与 UI 语言未对齐，直到搜索流程才暴露。
