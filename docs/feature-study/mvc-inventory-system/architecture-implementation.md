## 当前实际架构

当前已有数据到 UI、物品使用和拖拽内存操作链路，还没有持久化或数据库架构：

- `main.unity`：保存 Canvas、`InventoryWindow`、搜索区、格子容器和 `ContextPanel` 等固定 UI；Canvas 保持激活，窗口和菜单初始隐藏。
- `InventorySlot.prefab`：定义重复格子的 UI 外观、图标层和数量文本并挂载 `InventorySlotView`；场景中的格子是该 Prefab 的实例。
- `InventoryWindowView`：挂在 Canvas 上，监听 B 键，只切换 `InventoryWindow`，统一管理菜单与模态面板、保存唯一目标格，并判断拖拽屏幕点是否位于背包窗口矩形内；监听搜索文本变化，在模态期间禁用搜索输入。
- `DiscardConfirmationPanel`：场景中固定的丢弃确认界面；确认按钮交给 Controller 删除当前目标的完整持有记录，取消按钮只关闭面板并清理目标。
- `SplitPanel`：场景中固定且初始隐藏的拆分界面，包含整数滑条、拆分数量文本和确认/取消按钮；显示时保留唯一目标格，结束时统一清理。
- `InventorySlotView`：保存自身格子编号与是否有物品的显示状态；右键有物品格时传递菜单目标和可拆分状态；左键拖拽结束时把合法目标格交给 Controller，未命中格子时区分窗口内回退与窗口外丢弃确认；模态确认期间拒绝格子交互；按 Controller 的匹配结果切换格子底色。
- `ItemDefinition`：共享物品定义，保存稳定 `code`、显示名、Sprite 图标、使用效果和最大堆叠数。
- `InventoryItemData`：玩家当前格子数据，保存 `itemCode`、`slotIndex` 和 `quantity`；可在约束内移动、交换、向同类记录转移数量，或拆出一条位于目标空格的同类记录。
- `InventoryController`：由原显示控制器改名而来，拥有当前 Demo 的物品定义、动态玩家物品列表、人物生命值和格子引用；负责数据显示、使用效果、移动/交换/堆叠、查询最前空格并协调拆分记录加入集合，以及按显示名称匹配当前物品并驱动格子高亮。
- `PlayerHealth`：人物生命值状态与恢复上限规则，不依赖 UI。
- `PlayerHealthView`：把人物生命值显示到场景中的 `PlayerHealthPanel`。

当前调用方向为：`B 键 -> InventoryWindowView -> 背包窗口`；`有物品格子右键 -> InventorySlotView 传递 slotIndex 与可拆分状态 -> InventoryWindowView 保存唯一目标并显示菜单`；`拖拽结束未命中格子 -> View 判断屏幕点 -> 窗口内恢复 / 窗口外保存来源并显示丢弃确认框`；`DiscardButton` 也显示同一确认框；`ConfirmButton -> Controller 查找目标记录 -> 从 inventoryItems 删除 -> 刷新格子 -> View 关闭确认框并清理目标`；`CancelButton -> View 关闭确认框并清理目标，不修改数据`。搜索链路为：`TMP_InputField.onValueChanged -> InventoryWindowView -> InventoryController.ApplySearch -> ItemDefinition 显示名匹配 -> InventorySlotView.SetHighlight`；数据刷新后按当前输入重新计算高亮，搜索全程不修改玩家物品数据。

- 实际调整：接受四个高层阶段；当前只细化第一条 UI 骨架流程。

### 变化 4：从用户行为流程生成最小 UI 技术骨架

- 用户给出的顺序：B 键打开表格；添加搜索区；右键格子显示三个选项；暂不实现业务功能。
- AI 补充：把行为翻译为画面创建、窗口状态、格子右键三个职责，并使用项目已有的 uGUI 与 Input System。
- 实际结果：新增三个 UI 脚本，完成结构编译和自动行为校验；没有提前加入数据类型、MVC Model、背包规则或数据库代码。

### 变化 5：固定 UI 从代码创建改为场景与 Prefab 编辑

- 触发证据：运行时代码包含全部布局细节，用户无法在 Unity 编辑器中直接调整固定窗口，后续图标、拖拽和布局修改会继续扩大 `InventoryUiBootstrap`。
- 用户方案：在 Unity 中搭建固定背包界面；窗口保存在 `main` 场景，重复格子使用 Prefab；`InventoryWindowView` 保留输入和交互职责，Bootstrap 删除。
- 规范化：Canvas 始终激活并承载控制器，只切换 `InventoryWindow`；右键复用场景中的 `ContextPanel`，不创建菜单或重复判断命中对象。
- 实际结果：`InventoryUiBootstrap` 已删除，场景引用和 Slot Prefab 组件已由 Unity API 保存，`main` 成为首个启动场景。搜索和菜单命令仍没有业务行为。

### 变化 6：从单个混合物品结构演进为定义与持有数据

- 用户初始方案：一个 struct 同时保存类型、数量、`code`、名称、图标、描述和特殊规则，格子直接读取并显示。
- 触发问题：共享显示信息会在每个玩家格子记录中重复；类型 ID 不能区分同类别下的苹果和药水；数量和格子位置被误命名为 ID。
- 用户修正：使用唯一稳定 `code` 区分物品；先通过 `itemCode` 找共享定义，再把定义和数量交给 `slotIndex` 对应的格子。
- 规范化：`ItemDefinition` 与 `InventoryItemData` 分开；`InventoryDisplayController` 负责两次查找，`InventorySlotView` 只显示 Sprite 与数量。
- 实际结果：场景中的示例数据可让第一格显示 3 个苹果，其余 35 格保持空白；Play Mode 状态校验通过。

### 变化 7：格子身份与唯一菜单目标分离

- 触发证据：空格子也能打开物品菜单，且菜单只知道点击坐标，不知道未来命令应操作哪个格子。
- 用户方案演进：先提出由格子传递 `slotIndex`，随后澄清每格只应保存自身身份，唯一当前目标应集中保存在菜单所有者。
- 规范化：`InventorySlotView` 保存自己的 `slotIndex` 和 `hasItem`；右键有物品格子时传递编号；`InventoryWindowView` 保存一个可空的 `currentTargetSlotIndex` 并在隐藏菜单时清空。
- 实际结果：空格不再打开菜单；右键不同物品格会替换唯一目标；关闭菜单后目标为 `null`，Play Mode 校验通过。

### 变化 8：丢弃确认框复用菜单目标

- 用户方案：确认框由场景创建，点击丢弃时调用显示函数，确认和取消调用隐藏函数。
- 触发问题：现有 `HideContextMenu()` 会清空目标；进入确认框时调用它会让未来确认丢弃失去操作对象。
- 用户修正：确认框打开期间保留目标，待用户作出选择后清空。
- 规范化：切换到确认框时只隐藏右键菜单画面；确认、取消和关闭背包统一关闭确认框并清空目标。按钮使用 uGUI `Button.onClick`，不重复实现指针接口。
- 实际结果：场景按钮和面板已绑定，状态流校验通过；本流程不修改物品数据。
- 完成后修正：窗口公开只读确认状态，格子在点击入口统一早返回，避免确认期间通过左键清空目标或右键替换目标。

### 变化 9：拖拽视觉与真实内存行为合并构建

- 待决问题：阶段 1 是否需要先制作不改变数据的拖拽视觉骨架。
- 评审结论：单独拖拽视觉没有完成背包结果，阶段 3 接入移动、交换和合并时还会调整同一调用链。
- 最终决定：阶段 1 到丢弃确认 UI 为止；拖拽视觉与“拖到空格后内存位置真正改变”一起进入阶段 3，再逐步复用于交换、合并和拖出丢弃。

### 变化 10：从数据显示控制器演进为使用流程控制器

- 触发证据：阶段 2 要从当前目标格子查找玩家物品和共享定义，执行人物效果、消耗数量并刷新两个视图，原控制器已经不再只负责显示。
- 调整：`InventoryDisplayController` 保留 `.meta` GUID 并改名为 `InventoryController`；新增 `PlayerHealth` 与 `PlayerHealthView`，定义负责描述效果，Controller 负责解释和协调。
- 当前结果：苹果定义为恢复 10 点生命值；Use 按钮执行目标查询、生命值恢复、数量消耗和 UI 刷新，数量为 0 时格子显示为空。

### 变化 11：数量归零从“仅隐藏”改为删除持有记录

- 触发证据：原 `ConsumeOne()` 把数量减到 0 后，`RefreshSlots()` 只是不显示该记录；画面为空但 `inventoryItems` 中仍保留 slot 0 的零数量苹果，会使后续移动、拆分和持久化无法唯一判断空格。
- 用户方案演进：先提出让单条数据自行删除，随后修正为由拥有整个集合的 `InventoryController` 删除对应记录。
- 规范化：单条 `InventoryItemData` 只负责扣减数量；Controller 在效果和消耗成功后检查状态，并从动态集合中移除归零记录。
- 实际结果：`inventoryItems` 从数组改为 Unity 可序列化的 `List<InventoryItemData>`；场景初始数据保持不变，数据路径与正式编译已验证，等待 Game 视图确认。

### 变化 12：拖拽视觉与真实位置修改形成首条内存行为

- 用户方案：检测鼠标拖动，让物品跟随；非法落点回退；合法落点在目标创建记录并删除源记录。
- 数据修正：移动不创建或删除持有物品，而是让同一条 `InventoryItemData` 修改 `slotIndex`，从而保留物品身份、类型和数量。
- 职责结果：格子接收拖拽输入；窗口管理 Canvas 顶层共享拖拽图标；Controller 查询真实占用并执行空格移动规则；单条持有数据维护位置字段。
- 当前边界：只允许移动到空格；原格、背包外和占用格回退。交换、堆叠与拖出丢弃继续作为后续独立流程。

### 变化 13：已占用目标从回退扩展为交换或堆叠

- 用户规则：不同物品交换两条记录的 `slotIndex`；相同物品向目标剩余容量转移数量；目标已满时也交换位置。
- 数据补充：`ItemDefinition.maxStackSize` 同时表达是否可堆叠和数量上限，避免与单独布尔字段产生矛盾。
- 职责结果：Controller 查询两条记录并选择规则；`InventoryItemData` 只执行受约束的位置交换或数量转移；来源数量归零仍由拥有集合的 Controller 删除。
- 当前结果：空格移动、不同物品交换、部分堆叠、完整合并和满堆交换均已通过隔离 Unity 状态验证。

### 变化 14：最大堆叠数从操作条件提升为数据进入不变量

- 触发证据：移动合并会限制目标上限，但场景或未来数据库可以直接载入数量超过 `ItemDefinition.MaxStackSize` 的单条记录。
- 用户方案演进：先提出在持有数据中统一限制 10；发现不同物品上限不同后，修正为由同时拥有定义和记录的 Controller 检查；最终决定超出部分按空格顺序拆分，容量不足整体拒绝。
- 职责结果：Controller 在首次显示前规划所有记录的空格容量；`InventoryItemData` 根据已确认的目标格创建同类拆分记录；`RefreshSlots()` 不承担数据修复。
- 一致性结果：所有空格足够才应用拆分；任一记录容量不足时原列表完全不变，背包不进入可操作状态。

### 变化 15：零数量记录从不可见残留改为成功载入后清理

- 触发证据：零数量记录不会显示，也不会被操作查询命中，但仍保留在 `inventoryItems`，形成 Model 与 UI 不一致。
- 用户决定：在背包进入可操作状态前删除零数量记录。
- 原子性约束：扫描时只收集待删除记录；格子、定义和拆分容量全部验证成功后才统一删除，载入失败时原列表不发生部分修改。
- 当前结果：零数量和空引用会在成功规范化后清理；失败用例保持原数据，隔离 Unity 验证与正式编译均通过。

### 变化 16：从载入超限拆分扩展为玩家主动拆分

- 用户流程：右键可拆分物品，使用整数滑条选择数量，确认后放入编号最小的空格；数量不足或没有空格时按钮不可点击。
- 职责结果：格子只查询入口状态；窗口管理固定面板、滑条和目标生命周期；Controller 重新校验来源与空格并协调集合变化；单条数据负责受约束地产生拆分记录。
- 一致性结果：`TrySplit()` 在全部参数合法前不修改来源；确认时重新查找最前空格，成功后才加入目标记录并刷新画面。
- 场景结果：`SplitPanel` 与三个按钮回调已保存到 `main.unity`，自动行为和场景连线验证通过。

### 变化 17：丢弃确认框从纯 UI 状态连接到真实集合删除

- 原状态：确认和取消按钮都只关闭面板，物品数据完全不变。
- 用户规则：确认删除当前格整组物品，取消保持数据不变。
- 职责结果：View 保留目标与面板状态；Controller 拥有并删除 `inventoryItems` 中的记录；单条物品数据不负责把自己从集合移除。
- 当前结果：确认删除、取消保留和场景按钮回调均通过隔离 Unity 验证。

### 变化 18：拖出背包复用丢弃确认流程

- 用户规则：拖出背包不立即删除，而是等价于点击丢弃，先显示同一确认框。
- 边界修正：未命中格子不等于窗口外；搜索框和窗口空白区域属于窗口内非法落点，只恢复原显示。
- 职责结果：Window View 使用 `RectTransformUtility` 判断屏幕点；Slot View 选择移动、回退或丢弃确认分支；既有 Controller 删除逻辑保持不变。
- 当前结果：窗口内回退、窗口外确认和确认后删除均通过隔离 Unity 验证。

### 变化 19：搜索从预留输入框连接到只读高亮流程

- 用户规则：输入时立即按名称部分匹配，同种物品分布在多个格子时全部高亮；清空或无匹配时恢复原色。
- 数据边界：搜索状态属于 View，不写入 `InventoryItemData`；Controller 只读取定义和玩家物品集合，并把匹配格编号交给格子外观。
- 生命周期修正：`RefreshSlots()` 后按输入框当前文本重新计算，使物品移动后高亮跟随新位置；拆分或丢弃模态打开时禁用搜索，关闭后恢复。
- 当前结果：大小写无关的完整名和部分名、多结果、无结果、清空、刷新跟随以及模态开关共 8 项 Play 行为验证通过。名称搜索已完成；类型、标签和中文字体支持按已确认范围推迟。
