# 需求与用户流程文档

## 用户提出的流程

玩家打开背包后，可以查看背包中的物品，并对物品执行移动、交换、堆叠合并、拆分、搜索、使用和拖出丢弃。会改变背包的数据操作需要正确保存到本地 MySQL；搜索只改变显示结果。

## AI 流程评审

### 已覆盖需求

- 背包打开与物品查看。
- 空格移动和物品交换。
- 堆叠合并与拆分。
- 搜索、使用和丢弃。
- 数据加载与保存。

### 遗漏场景

- 首次打开时数据库为空或连接失败。
- 目标堆叠已满、拆分数量非法、目标格被占用。
- 使用效果失败或目标状态不允许使用。
- 丢弃确认取消、拖拽中途取消或关闭背包。
- 保存失败时 UI 与已保存数据可能不一致。

### 异常与边界

- 非法操作必须保持原状态并给出反馈。
- 搜索不得改变物品真实格子位置。
- 任何失败都不应导致 Demo 崩溃、复制物品或丢失物品。
- 客户端只展示当前玩家需要的背包数据，不处理全量玩家数据。

### 需要用户修正

- 当前没有阻塞施工路线设计的流程缺口。
- 背包容量、交互入口和具体提示文案可在对应流程施工前确认。

## 用户修正后的流程

### 打开背包

入口：玩家按快捷键或点击背包按钮。

操作：系统读取当前 Demo 玩家数据。

系统反馈：显示加载状态；成功后显示格子、物品和数量，失败时显示错误与重试反馈。

最终结果：玩家看到可操作背包，空背包也能正常显示。

### 移动、交换与合并

入口：玩家开始拖拽物品。

操作：将物品释放到空格或已有物品的格子。

系统反馈：空格时移动；不同物品时交换；同种可堆叠物品时按容量合并；非法目标保持原状并提示。

最终结果：界面和已保存背包状态一致。

### 拆分

入口：玩家对可堆叠物品选择拆分。

操作：输入合法数量并选择空格。

系统反馈：非法数量或非空目标被拒绝；合法时显示源格剩余数量和目标格新堆叠。

最终结果：拆分结果正确保存，失败时不产生部分变化。

### 搜索

入口：玩家输入名称、类型或标签。

操作：系统过滤或高亮当前已加载物品。

系统反馈：立即更新显示结果。

最终结果：真实格子和保存数据不变。

### 使用

入口：玩家选择使用某件物品。

操作：系统判断是否可使用并尝试执行效果。

系统反馈：成功时显示效果和剩余数量；失败时说明原因且不消耗物品。

最终结果：至少一种具体效果可以验证，数量变化正确保存。

### 丢弃

入口：玩家把物品拖出背包或选择丢弃。

操作：确认丢弃全部或指定数量。

系统反馈：取消时保持原状；确认时更新物品数量或移除物品。

最终结果：界面和已保存数据一致。

## 验收标准

1. 打开背包后能显示固定 Demo 玩家当前物品、数量和空格。
2. 空背包、连接失败和加载失败都有明确状态，不导致崩溃。
3. 物品可以移动到空格，并在重新加载后保持位置。
4. 两个不同物品可以交换位置并正确保存。
5. 同种可堆叠物品可以合并，且不会超过最大堆叠数。
6. 可堆叠物品可以拆分到空格，失败时不会只保存一部分结果。
7. 搜索能够按名称、类型或标签过滤或高亮，不改变真实数据。
8. 使用物品能够产生至少一种可见效果；失败时不扣减数量。
9. 丢弃必须确认，确认后能够删除或减少数量，取消时保持原状。
10. 非法操作和保存失败有可见反馈或日志，不复制或丢失物品。
11. 物品定义数据和玩家物品实例数据能够被分别表达和读取。
12. 文档明确本地 MySQL Demo 与生产服务器架构的区别。
